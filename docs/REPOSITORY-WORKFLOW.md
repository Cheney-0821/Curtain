# Curtain 单一工作区规则

- 维护一个源码工作区、一个长期开发分支 `main` 和一个公开 GitHub 源代码仓库。
- 每轮先在本地工作区修改、编译、验证，再由维护者明确决定是否提交及推送。
- 公开仓库以现有 GitHub `main` 祖先链为基线；不修改已经公开的提交或历史标签。
- 旧内部开发历史使用单独、可验证的离线 bundle 归档，不直接并入公开提交链，以防历史文档泄露。
- 发布时在当前源码树中执行构建。临时构建目录与离线归档不构成第二个长期源码工作区。
- `reports/`、`artifacts/`、`development-log/`、旧版私有文档和本机 R2 脚本属于维护材料；当前 `.gitignore` 排除这些本机文件，暂存前仍须检查 `git ls-files`。
- `git add -A` 不能代替公开文件清单审核；尤其要检查被忽略之外的未跟踪文件。
- 对外推送应明确指定 `main:main`，不能使用 `--force`、`--mirror` 或 `--all`。
